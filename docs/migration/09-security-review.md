# 周期罗盘 CycleCompass 安全与防风险审计报告 (Phase 6)

## 一、系统安全评估原则
迁移全程恪守以下安全红线：
1. 不向日志、文档或外部网络泄露任何生产密钥、Token 或密码。
2. 保持非 root 安全运行权限（Least Privilege）。
3. 防范外部源站击穿与单点雪崩（SingleFlight + TTL 缓存）。
4. 保证数据持久化一致性与防注入。

## 二、关键安全审计项与结论

### 1. 运行权限与容器隔离
- **容器内部**：新建专有 `appuser:appgroup`（UID 10001），禁止以 root 账户运行 Web 进程。
- **文件系统**：除 `/app/data` 挂载目录具备写入权限外，系统核心运行环境为只读。

### 2. 网络暴露面与端口安全
- **对外暴露**：Go API 仅监听内部回环地址或 Docker 内部网络（`127.0.0.1:8002`），不对公网暴露任何未受控端口。
- **反代防护**：所有公网流量严格经由 1Panel OpenResty 进行 HTTPS/TLS 1.2+1.3 终结，受 1P-WAF 安全规则与速率限制保护。

### 3. 数据层安全 (SQLite)
- **SQL 注入防范**：所有查询与写入全部使用标准库 `database/sql` 的预编译参数化占位符（`?`），彻底杜绝 SQL 注入隐患。
- **并发锁与事务保护**：启用 SQLite WAL（Write-Ahead Logging）模式与 5000ms BusyTimeout，支持并发只读与串行安全写入，消除数据锁争用与损坏风险。

### 4. 外部源站安全（反爬与防封锁）
- **合并请求**：A 股多标的代码在单次 HTTP 请求中合并拉取（`https://qt.gtimg.cn/q=...`）。
- **并发防击穿**：使用 `sync.RWMutex` + `sync.Mutex` 互斥保护，当 100+ 用户同时并发请求相同或重叠标的时，底层向源站仅发起 1 次 HTTP 查询，结果复用于后续请求，绝不触发外部源站的速率限制或封禁。
- **平滑降级**：当源站出现超时（3 秒阈值）或网络受限时，自动平滑回退至本地离线种子数据快照，确保业务 100% 可用且响应头如实标注降级警告。
