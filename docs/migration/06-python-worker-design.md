# Phase 2: Python Worker 保留与调度设计规范

## 一、 职责明确切分

- **Go API 的边界**：
  - 承载小程序前端全部 HTTP 请求（99% 为行情查询、页面指标、模拟账户读取、常用回测结果）。
  - 执行极速 I/O 与高并发组装。
- **Python 的边界（核心计算库与 Worker）**：
  - 彻底保留现有的 Python 核心库：
    - `packages/strategy_engine/`（四维评分算法、双策略轮动推演、资金守恒审计规则）
    - `packages/backtesting/`（牛顿迭代 XIRR 求解、最大回撤、夏普比率计算）
    - `packages/market_data/`（数据清洗模型与离线校验）
  - 定时离线补数与日终历史数据归档更新。

---

## 二、 运行模式演进：从常驻 HTTP 进程变为按需任务

1. **避免双常驻进程占满内存**：
   - 现有的 `cycle-compass-api` 容器作为旧服务在灰度期间保持监听内部端口（如 `127.0.0.1:8001`）。
   - 在新 Go API 完全承接公网流量并通过验收后，停止常驻的 FastAPI HTTP 服务，释放出 **~200MB** 内存。
2. **回测任务的混合协同模式**：
   - **常规默认与高频参数回测**：Go API 内部基于历史日 K 线数据实现经过算法校验的一致性轻量引擎，带 LRU 结果缓存，0ms 返回；
   - **超深度长周期历史计算**：如果遇到自定义复杂参数，由 Go 触发内部 Python 脚本或共享任务队列处理，实现动静分离。
